F-PSheet — Build a Product Sheet from One Photo

What you'll learn

How to take one photo of a product and produce a multi-angle product sheet that becomes the reference for every product shoot you ever do for that SKU.

A character sheet locks identity for people. A product sheet locks identity for objects. Without one, every generation invents a slightly different watch, a slightly different bottle, a slightly different sneaker. With one, the same object appears across hero, lifestyle, tabletop, ad — with pixel-level consistency.

The result you're building (one input → this sheet)

Five angles: three-quarter hero / dead-front / profile / top-down / detail macro. Same watch, same finish, same scale, same lighting.

The 5-angle product sheet

Shot 1

  • Angle: Three-quarter HERO
  • Why it's locked: The marquee shot. The brand-recognition cue.

Shot 2

  • Angle: Dead front
  • Why it's locked: Flat, centered, dial / label / logo readable.

Shot 3

  • Angle: Profile
  • Why it's locked: Depth, edge geometry, thickness.

Shot 4

  • Angle: Top-down
  • Why it's locked: Flat-lay master.

Shot 5

  • Angle: Detail macro
  • Why it's locked: Tight crop on the most premium detail.

Recipe F.PSHEET.01 — 5-angle product sheet

JSON-structured for Nano Banana Pro. Attach the client's one product photo as the reference.

{
  "image_type": "studio product reference sheet, single composite image",
  "subject": "the product from the reference image — do not redescribe its surface, dial, or details",
  "layout": "horizontal grid of 5 angles, equal spacing, clean bone-white seamless studio backdrop, identical scale across cells",
  "angles_left_to_right": [
    "THREE-QUARTER HERO view — the marquee angle, dial / face / logo prominently visible",
    "DEAD-FRONT view, perfectly flat, centered",
    "PROFILE / SIDE view, showing depth and edge geometry",
    "TOP-DOWN flat-lay view from directly above",
    "DETAIL MACRO — tight crop on the most premium detail"
  ],
  "surface": "the same clean bone-white seamless backdrop on every cell",
  "lighting": "single soft top-key + subtle fill, identical across all 5 angles",
  "camera_lens": "Phase One IQ4, 120mm macro f/8, tack sharp throughout",
  "color_grade": "clean editorial, faithful tones, no LUT, premium product palette",
  "same_product_across_all_angles": true,
  "same_finish_across_all_angles": true,
  "same_scale_across_all_angles": true,
  "no_different_product_between_angles": true,
  "no_color_shift_between_angles": true,
  "no_surface_description": true,
  "identity_lock_strength": "high",
  "anti_drift_reinforcement": [
    "every angle must show the SAME product — same finish, same dial, same proportions, same logo placement",
    "every angle must use the SAME backdrop and the SAME lighting direction and quality",
    "the sheet is a single coherent reference asset, not five separate generations"
  ]
}
Why no surface description. Same logic as F3 for faces. The instant you write "brushed steel case with leather strap," the model re-imagines the watch from your words and overrides the reference. Trust the reference. Spend words on the world (backdrop, lighting, angle) — never on the object itself.

Workflow

  1. Get the cleanest input. Sharp iPhone snap on a clean surface is fine. Single product, in focus, tight crop.
  2. Open Higgsfield → Nano Banana Pro. Attach the input. Aspect 16:9, resolution 2k, variants 2.
  3. Paste Recipe F.PSHEET.01. Usually no slots to fill — the recipe is complete.
  4. Generate. Pick the cleaner variant. That's your sheet.
  5. Save it named after the SKU. Reuse on every downstream product shoot.

When this fails (troubleshooting)

Different finish on each angle

  • Likely cause: Input photo low-quality
  • Fix: Use sharper input or run F5 edit-one-element per cell

Logo / brand text drifts

  • Likely cause: Generators invent text
  • Fix: Add preserve_logo_exactly_as_reference: true

Scale wildly different between cells

  • Likely cause: Layout spec missed
  • Fix: Re-state "the product occupies the same proportion of each cell"

Looks rendered, not photographed

  • Likely cause: Default product-CGI bias
  • Fix: Add "photographed product, not 3D render" + "no CGI look"
